# CO binding-index mismatch

During the adsorption workflow test, the prompt requested carbon-bound CO, but the agent explicitly passed `binding_atom_indices=[0]` to `build_adsorbate`. ASE's built-in CO ordering is `[O, C]`, so oxygen is index `0` and carbon is index `1`. Passing `[0]` overrode the curated CO default (`[1]`). The resulting adsorbate artifact was `adsorbate_CO_446037c9564b9626.xyz`, and the candidate manifest recorded `[0]`.

Despite that recorded index, the generated structures were physically carbon-bound: in `candidate_000`, the initial nearest distances were C–Pt = 2.22 Å and O–Pt = 3.13 Å; after UMA relaxation they were C–Pt = 1.85 Å and O–Pt = 3.01 Å. Thus, the requested/recorded binding index and the FAIR Chemistry placement do not agree.

Later fix:

- Do not let the agent infer an atom index from the formula order. When no explicit index is supplied, use the curated value returned by `build_adsorbate`.
- Preserve and pass the returned `chemical_symbols`, `binding_atom_indices`, and `binding_atom_elements` together.
- Before candidate generation, validate that the requested binding element matches the selected source atom.
- After generation, validate geometrically that the declared binding atom is the adsorbate atom placed nearest the surface; otherwise return a typed, non-retryable error.
- Add focused tests for ASE CO ordering and for consistency between requested binding atom, manifest provenance, and generated geometry.
